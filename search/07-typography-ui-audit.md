# 07｜中文排版与首页「实习现场」UI 审计

> 审计对象：`index.html`、`css/style.css`、`css/evidence-ledger.css`
> 审计日期：2026-08-11
> 范围说明：本文件只审计本地实现与用户截图，不改站点代码。游戏 UI 的外部案例调研可作为另一份研究输入；本文件负责把研究结论约束成可执行的字号、层级和验收标准。

## 1. 结论先行

当前问题不是“内容太多”，而是**把工程感误写成了大量微型字、等宽字和细线**。这使重要信息看起来像调试面板的附注：信息存在，但读者必须费力辨认，专业感反而下降。

首页「实习现场」最明显：

- 教育经历与履历页重复，属于信息架构冗余，应从首页删除。
- 日期与公司名都只有 `0.72rem = 11.52px`，而公司名本应是一级上下文，不应被降成脚注。
- “查看完整履历”只有 `0.74rem = 11.84px`，关键操作被做成了难读的小字。
- 正文是正常的 16px，但它被 11.52px 的日期、11.52px 的公司名、13.76px 的教育脚注包围，因此整块仍显得轻、散、僵硬。
- 180px 的日期列与 32px 列间距制造了大面积空白；双横线、细字、等宽字共同形成“表格档案”感，而不是舒适的叙事栏目。

建议保留现有暖纸色、黑墨色和荧光绿信号色，但把首页体验从“工程日志表格”改成**艺术游戏常见的章节选择 / 档案卡片结构**：大标题、大编号、清晰状态、少量证据标签、完整可读的叙述。借用的是信息层级和焦点控制，不是照搬 HUD、任务框或游戏术语。

## 2. 为什么截图会显得不专业

### 2.1 CSS 级联把原本尚可的字号系统压小了

`index.html:25-26` 先加载 `style.css`，再加载 `evidence-ledger.css`。前者的基础 token 是：

| token | 像素值 | 原本用途 |
| --- | ---: | --- |
| `--text-xs` | 12px | 标签 / 次要元数据 |
| `--text-sm` | 14px | 辅助正文 / 操作 |
| `--text-base` | 16px | 正文 |

这套下限虽然保守，但可用。问题在于后加载的主题层大量使用 `0.52rem—0.74rem` 的任意值覆盖它。

以浏览器默认根字号 16px 计算，`evidence-ledger.css` 的 142 条数值型 rem 字号声明中：

| 区间 | 声明数 | 占比 | 判断 |
| --- | ---: | ---: | --- |
| `< 12px` | 71 | 50.0% | 只有装饰性图形标注可以使用；当前明显过量 |
| `12px—<14px` | 11 | 7.7% | 只适合非关键说明，不适合中文正文与 CTA |
| `14px—<16px` | 3 | 2.1% | 可用于元数据、辅助操作 |
| `< 16px` 合计 | 85 | 59.9% | 说明主题层系统性偏爱“小字造型” |

说明：以上统计的是 CSS 声明，不是页面实际元素数量；包含响应式重复声明和预览插画内部标签。但即便剔除纯装饰预览，首页仍有大量核心信息低于 12px。

### 2.2 字体声明并没有真正保证这些字体存在

`style.css:46-48` 声明了 Inter、Noto Sans SC、JetBrains Mono 和 Fira Code，但 `index.html` 没有加载或自托管这些字体。在常见 Windows 环境中会发生：

- 拉丁字母回退到系统无衬线或 Consolas；
- 中文再回退到微软雅黑等 CJK 字体；
- 同一行里的日期、英文与中文出现字面高度和笔画粗细不一致；
- `.ledger-experience-org` 被强制等宽，但中文并不存在真正的 JetBrains Mono 字形，于是产生二次回退。

这正是截图中“小字像临时标注”的一部分原因。工程站点不需要依赖远程中文 WebFont；中文字体体积大、国内网络也不稳定。优先使用可靠的系统 CJK 字体栈更合适。

### 2.3 “等宽 + 全大写 + 大字距”使用过量

当前把日期、公司、栏目序号、项目元数据、证据标签、技术标签、CTA 都做成了等宽字。等宽体适合代码、编号、英文状态和数字对齐，不适合中文公司名、中文操作和连续阅读。

此外 `font-weight: 750/850` 在不支持可变字重的系统中文字体上会被浏览器合成，容易出现笔画发糊。建议正文使用 400/500，强调使用 600/700；只有确认加载了可变字体时才使用中间字重。

### 2.4 颜色“技术上刚过线”，感知上仍然吃力

| 前景 / 背景 | 对比度 | 结论 |
| --- | ---: | --- |
| `#666d67` / `#f3f0e8` | 4.67:1 | 刚过 WCAG AA 普通文本线；11px 小字、细笔画和网格背景下仍吃力 |
| `#858b85` / `#f3f0e8` | 3.06:1 | 不适合普通大小的有意义文本 |
| `#171a18` / `#f3f0e8` | 15.40:1 | 主文本清晰 |
| `#c9c6bb` / `#f3f0e8` | 1.50:1 | 只可作为分隔线，不可承载文字 |

小字不应只追求 4.5:1 的最低线。建议 14px 元数据也尽量达到 7:1 左右；正文继续使用深墨色，弱化应通过层级、位置和字重完成，而不是同时“缩小 + 变灰”。

## 3. 首页中低于 12 / 14 / 16px 的实际用途

### 3.1 `< 12px`：核心信息不应出现在这里

| 选择器 | 实际字号 | 当前用途 | 判断 |
| --- | ---: | --- | --- |

| `.hero-pin-kind` | 9.28px | 入口类型 | 有意义，过小 |
| `.hero-featured-number` | 9.60px | `CASE / 01` | 纯装饰时可保留 |

| `.hero-featured-head` | 9.92px；移动端 8.64px | 旗舰案例类型 / 状态 | 状态有意义，不应在移动端进一步缩小 |

合理保留 `<12px` 的唯一场景：CSS 绘制的文章预览图内部坐标、终端假数据、装饰编号，并且这些内容必须是 `aria-hidden` 或不是理解页面所必需的信息。

### 3.2 `12px—<14px`：只能承担非关键辅助信息

| 选择器 | 实际字号 | 当前用途 | 判断 |
| --- | ---: | --- | --- |
| `.ledger-availability` | 12.16px | 毕业 / 可实习状态 | 招聘方关心，建议 14–15px |
| `.hero-pin-copy` | 12.32px | 入口核心简介 | 连续中文，建议 15–16px |
| `.nav-logo` | 12.48px | 品牌缩写 | 可以 |
| `.ledger-education-line` | 13.76px | 教育经历 | 字号勉强，但信息重复；应直接删除 |

### 3.3 `14px—<16px`：适合元数据，不足以承担主要阅读

| 选择器 | 实际字号 | 当前用途 | 判断 |
| --- | ---: | --- | --- |
| `.ledger-button` | 14.08px | 按钮 | 可用，建议关键按钮 15–16px |
| `.hero-featured-copy` | 14.08px | 旗舰项目说明 | 可读但偏小，建议 16px |
| `.ledger-resource-item > span:nth-of-type(2)` | 14.08px | 资源说明 | 最低可用；若是连续中文建议 15–16px |
| `.ledger-name > small`（桌面上限） | 14.72px | 英文姓名 | 非主要信息，可以 |

首页普通段落继承 `body` 的 16px / 1.7 行高，是当前比较舒服的基准。重构不应把所有文字一律做大，而应把**重要信息恢复到 14–17px**，把 10–12px 限制在纯装饰层。

对应结构：`index.html:272-300`；样式：`evidence-ledger.css:1328-1366`、`1566-1600`。

## 5. 中文优先的字号与字体 token

建议在主题层统一覆盖，停止继续添加 `.61rem`、`.68rem` 这类零散数值：

```css
:root {
  --font-ui: system-ui, -apple-system, BlinkMacSystemFont,
    "Segoe UI", "PingFang SC", "Hiragino Sans GB",
    "Microsoft YaHei UI", "Noto Sans CJK SC", sans-serif;
  --font-code: ui-monospace, "SFMono-Regular", Consolas,
    "Liberation Mono", monospace;

  --type-decorative: 0.75rem;   /* 12px：仅装饰、预览图内部文字 */
  --type-caption: 0.8125rem;    /* 13px：非必要图注 */
  --type-meta: 0.875rem;        /* 14px：日期、标签、状态 */
  --type-action: 0.9375rem;     /* 15px：CTA、导航辅助入口 */
  --type-body: 1.0625rem;       /* 17px：中文正文 */
  --type-body-lg: 1.125rem;     /* 18px：导语、重点摘要 */
  --type-card-title: clamp(1.625rem, 2.6vw, 2rem); /* 26–32px */
  --type-section-title: clamp(2.75rem, 5vw, 4.75rem);
}
```

使用规则：

1. 中文正文默认 17px / 1.75；窄屏不再主动缩小正文。
2. 所有可交互文字至少 15px，点击区域至少 44px。
3. 所有有意义的元数据至少 14px；小于 12px 的内容不能是唯一信息来源。
4. 等宽体只用于代码、纯数字编号和短英文状态；中文公司名、中文 CTA、中文标签使用 `--font-ui`。
5. 日期使用 `font-variant-numeric: tabular-nums`，不需要为了数字对齐把整行切成等宽字体。
6. 中文大标题字距建议 `-0.02em` 左右，行高 1.05–1.10；不要套用英文海报的 `-.055em / .93`。
7. 优先使用 400 / 500 / 600 / 700 四档字重，避免未加载可变字体时合成 750、850。
8. 弱化信息只使用一种手段：减小字号、变浅颜色、降低字重三者不要同时叠加。

## 6. 首页经验板块重构建议

### 6.1 内容层级

栏目保留“实习现场”，删除教育行。每段经历只呈现五层：

1. 大号章节编号 `01 / 02`（装饰锚点，可低对比）；
2. 日期 + 状态（14px，例如“现场课题”“企业交付”）；
3. 公司 / 计划（16–17px、500/600）；
4. 职位标题（26–32px、650/700）；
5. 17px 摘要 + 2 至 3 个结果标签（14px）。

建议结果标签直接使用已有事实：

- 友达光电：`OpenSOP Agent`、`40 OI / 324 Step`、`独立重构`；
- 福建新意：`Dify / Hybrid RAG`、`20 Golden Cases`、`多模型接入`。

这能把招聘者真正要找的“在哪里、做什么、结果如何”放在一次视线扫描内。

### 6.2 视觉结构：章节卡片，而不是 HUD 表格

推荐桌面端使用两张并排卡片，移动端单列：

- 当前经历作为主卡，使用深墨底 / 暖纸文字 / 荧光绿焦点条；
- 上一段经历使用浅纸面板 / 深墨文字 / 珊瑚色编号；
- 卡片左上角放大 `01 / 02`，但它只是空间锚点；
- 日期和状态位于同一头部，不再占用固定 180px 空列；
- 摘要控制在约 28–34 个中文字符的视觉行长；
- 整卡可链接到 `resume.html#experience`，同时保留明确的“查看完整履历”文字；
- hover / focus 只做 2–4px 位移、边框或焦点条变化，不做炫光和持续动画。

从艺术游戏 UI 借用的是：**章节感、强焦点、空间锚点、选中态与逐层揭示**。不要借用微型遥测、密集边框、准星、扫描线或伪终端；当前站点的问题恰好就是过度接近这类 HUD。

## 7. 整站整改优先级

### P0：本轮必须处理

- 删除首页教育行。
- 把 `.ledger-experience-date`、`.ledger-experience-org`、`.ledger-section-link` 提升到 14–16px，并取消中文等宽体。
- 将经验区改为卡片 / 章节式结构，消除固定 180px 空列和重复横线。
- 移动端删除 `.hero-featured-head { font-size: .54rem; }` 这类“屏幕越小、字越小”的规则。

### P1：整站统一

- 把项目状态、证据标签、结果数据、CTA 全部提高到 14px 以上。
- 让 `.hero-pin-proof`、`.hero-featured-proof` 等关键结果至少 14–15px。
- 用统一 token 替换 `.58rem`、`.61rem`、`.66rem`、`.68rem`、`.72rem` 的散点字号。
- 修正 `--text-muted: #858b85` 被用于普通文本的场景；小文本优先使用更深的中性色。
- 将中文标题的极端负字距和过紧行高收敛。

### P2：可保留的小字

- 文章预览图里的 terrain / terminal / pipeline 装饰标签；
- 不承载项目结果的 `CASE / 01` 等编号；
- 非必要图片说明。

这些内容应明确是装饰层，不能替代可访问文本。

## 8. 验收标准

- 在 Windows 100% 缩放、1366px 和 1920px 宽度下，首页所有有意义文本不低于 14px。
- 在 390px 宽度下，正文和元数据不因媒体查询进一步缩小；无横向滚动。
- 公司、职位、结果三项可在 3 秒内完成视觉扫描，不需要先阅读灰色小字。
- 中文公司名、中文 CTA、中文标签不使用等宽字体。
- 14–16px 文本对比度至少 4.5:1，目标 7:1；`#858b85` 不承载普通正文。
- CTA 字号至少 15px、可点击区域至少 44px，并有可见键盘焦点。
- 大标题在两行时不重叠，行高不低于 1.05。
- 首页不再展示教育经历；教育只在履历页出现。
- 纯装饰微型文字若不可读，不影响理解，并从无障碍树中隐藏。

## 9. 核心判断

专业感不等于更小、更灰、更像终端。当前视觉方向的颜色和工程主题是成立的，真正需要纠正的是**信息密度的表达方式**：用更少的层级、更大的有效字号、更可靠的中文字体、更明确的焦点来表达工程能力。艺术游戏 UI 最值得学习的也不是装饰，而是它让读者在舒服的节奏里知道“现在看哪里、下一步去哪里”。
