我是宋林蔚。比起一次看起来聪明的回答，我更关心系统是否知道依据来自哪里、失败后如何继续、以及最后由谁确认。

01

WHY I BUILD

模型生成的是候选，
工程交付的是可信过程。

我的实践从企业客服 / 运维知识问答出发，延伸到制造业 SOP、本地桌面小模型 Agent 与对话式企业知识沉淀。这些场景看起来不同，却都要求系统在不确定信息、权限变化和失败恢复中保持边界。

因此，我会先设计状态、证据与人工关口，再决定模型放在哪一步。研究上，我也在探索如何用模型内部注意力与显式证据状态，让多跳检索的下一步更可解释、更可复核。

02

ENGINEERING PRINCIPLES

四条工程原则

01

Evidence before eloquence

先确定来源、时间、权限和适用边界，再让模型组织语言；没有证据的内容不由 LLM 补齐。

02

State before orchestration

把当前步骤、中间结果和失败状态显式建模。暂停、恢复与重试应是工作流的一部分。

03

Permission before retrieval

先限定租户与可见范围，再进行召回、精排与生成；身份同步不能绕过知识权限。

04

Human owns the release

Agent 可以起草、校验和推荐候选，但生产 SOP 与共享知识的最终发布必须有人确认。

03

WORKING LOOP

我的工作方式

  1. Observe先还原真实流程

    确认使用者、输入、决策点与不能自动化的边界。

  2. Ground再绑定证据

    把结构化主数据、历史材料和用户原话变成可追溯依据。

  3. Recover让失败可恢复

    显式保存状态、幂等边界和重试入口，不让一次异常污染后续结果。

  4. Approve由人完成发布

    把确认与审核放进主路径，并保留版本与责任记录。
