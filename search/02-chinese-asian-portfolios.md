# 中文与亚洲开发者个人网站研究

> 调研日期：2026-08-09
> 范围：面向开发者、研究生与独立产品作者的个人首页、作品集、技术博客及公开源码。以下站点均在调研当日实际访问；“事实”来自站点或其公开仓库，“判断”是针对宋林蔚个人站改版的设计分析。

## 研究方法

以桌面端首屏和主要内容页为主，按五个问题检查：

1. 访客能否在 5 秒内知道“这个人是谁、做什么”？
2. 招聘者能否在 15 秒内找到代表项目与硬证据？
3. 中文、英文或双语内容是否自然，不造成重复阅读？
4. 博客、研究、项目和履历是否共同构成可信的能力证据？
5. 视觉记忆点是否会拖慢加载、遮挡内容或增加维护成本？

## 逐站分析

### 1. Anthony Fu：把“身份”写成可点击的项目关系图

- 链接：[首页](https://antfu.me/) · [Projects](https://antfu.me/projects) · [公开源码](https://github.com/antfu/antfu.me)
- 事实：首屏在姓名后直接给出角色、任职/团队关系，以及 Creator、Core team、Maintaining 三组项目；项目页再按 `Current Focus`、`Nuxt Ecosystem`、`DevTools`、`Vite Ecosystem` 等主题分组。
- 优秀点：不先讲抽象能力，而是把身份绑定到可点击的作品和生态。灰色项目标签嵌在自然语言中，信息密度高却仍能扫读；手绘枝叶背景提供个人辨识度，但正文仍是主角。
- 局限：这种极简表达依赖项目本身已有知名度；没有明确时间线，对需要核对教育、实习阶段的招聘者不够完整。
- 可迁移：宋林蔚首屏可采用“我正在构建 / 我研究 / 我交付”的三行证据句，将星途知汇、Local Window Copilot、论文和实习直接变成链接；Projects 页按“Agent 产品 / 本地智能 / 研究与评测 / 工具链”分组，而不是平铺仓库。

### 2. Innei：AI 定位与个人气质可以同时成立

- 链接：[站点](https://innei.in/) · [站点项目说明与源码](https://github.com/innei/Shiro)
- 事实：首页用 “I orchestrate ideas into products with AI Agents” 完成职业定位，随后接 Recent Writing、Projects、Says 等内容入口；界面提供中英文、明暗主题、RSS、订阅和社交入口。公开仓库说明该主题包含 Hero、时间线、多语言、Motion 动画与无障碍组件。
- 优秀点：大字号主句只强调一个关键词 `AI Agents`，配色和光标动效轻而明确；头像、诗句和留白给出人格，不需要堆叠技术 Logo。
- 局限：首屏占用接近一整屏，项目证据需要向下滚动；实时统计若尚未加载会出现 `0`，容易让访客误解。
- 可迁移：保留一句鲜明但可验证的主张，例如“把大模型能力做成可运行、可评测、可追溯的 Agent 系统”；动效只用于关键词状态切换，所有计数使用静态快照与更新时间，避免首屏依赖异步数据。

### 3. DIYgod：中文人格、照片和项目成果形成完整“人”的印象

- 链接：[站点](https://diygod.cc/) · [公开源码](https://github.com/DIYgod/diygod.me)
- 事实：首页为左右分栏：左侧是姓名、中文短句、自我描述和社交链接，右侧是真实生活照片；下方依次进入文章和项目，并提供中文/English 切换。
- 优秀点：真人照片与一句可记住的中文口号让站点摆脱模板感；文章和项目不是分裂的两个网站，而是同一主页上的两条证据线。文章卡带日期、类别、标签和摘要，项目区直接链接实际产品。
- 局限：高度个人化、俏皮的自述适合成熟开源作者，但求职站若照搬会稀释专业判断；代表项目仍在首屏以下。
- 可迁移：可采用一张克制的个人照片或工作场景图，与专业定位并列；人格化文案控制在一句，紧接两项旗舰项目和“查看履历”按钮。

### 4. Tw93：用强对比品牌区分博客，用摘要降低点击成本

- 链接：[站点](https://tw93.fun/) · [About](https://tw93.github.io/about) · [公开源码](https://github.com/tw93/tw93.github.io)
- 事实：顶部导航直接给出 Weekly、GitHub、Twitter、About 和英文入口；页面有高对比暗色横幅，文章卡展示发布日期、标题和较完整摘要，并支持键盘唤起搜索。公开仓库说明其模板强调响应式、懒加载、资源压缩，以及针对中国网络环境减少阻塞资源。
- 优秀点：一眼可识别的黑白视觉语言；摘要足够长，访客无需逐篇点击即可判断内容质量；搜索快捷键对长期博客很有效。
- 局限：主页是博客优先，人物身份和代表产品不在第一屏；大横幅虽然醒目，但占用了本可展示项目证据的高度。
- 可迁移：借用“强对比状态条”，内容改为 `LLM APPLICATION / AGENT ENGINEERING / AVAILABLE FOR ...`；文章列表沿用日期 + 一句话结论，但置于项目和履历之后。

### 5. Shu Ding：编辑式布局让极少内容显得成熟

- 链接：[站点](https://shud.in/) · [Projects](https://shud.in/projects)
- 事实：页面采用窄左栏章节导航（about / thoughts / projects / images）和宽正文区；About 只用三段文字说明当前角色、教育和 Microsoft、Vercel、Next.js、AI SDK 等经历，再给 GitHub、X、LinkedIn 链接。
- 优秀点：导航、正文和留白像一本编辑精良的小册子，读者不会迷路；职业叙述按“现在—来路—下一步入口”组织，而不是复述完整简历。
- 局限：桌面端留白较多，早期职业阶段若没有可识别的组织名，文本说服力会弱；项目缺少醒目的数字、截图和案例结论。
- 可迁移：在 Resume/Projects 页面使用粘性左侧目录；首页 About 只保留 80–120 字，将详细经历交给时间线，把宝贵首屏留给项目证据。

### 6. 冉熙 Xi Ran：与 AI Agent 求职最接近的直接参照

- 链接：[站点](https://ranxi.top/)
- 事实：页面提供中文/英文切换、English CV 和多种中文简历入口；桌面端由身份侧栏、主履历、导航侧栏构成，内容覆盖 About、Research、Industrial Experience、Education、Projects、Open Source Contributions，并大量使用 PR 数、仓库数、耗时和业务规模等量化证据。
- 优秀点：身份、学校、地点、联系方式和简历下载始终容易找到；经历条目用“方向 + 行动 + 数字结果”组织，特别适合招聘者快速核验；项目按技术域归类，并把开源贡献独立成证据区。
- 局限：中英文逐句并排/连续显示造成页面很长，阅读节奏被重复内容打断；三栏和密集正文对小屏不友好，个人视觉记忆点较弱。
- 可迁移：保留身份摘要栏、量化证据和分组项目，但中英文必须采用“整页语言模式”，一次只展示一种语言；首页只展示两项旗舰项目、两段经历和两篇研究成果，完整内容放 Resume 页面。

### 7. Takuya Matsuyama：签名式 3D 视觉应服务于身份，而不是遮挡身份

- 链接：[站点](https://www.craftz.dog/) · [Works](https://www.craftz.dog/works) · [公开源码](https://github.com/craftzdog/craftzdog-homepage)
- 事实：站点在顶部放置 3D voxel 作品，下面是姓名、Digital Craftsman 定位、头像、Work、Bio、产品和频道；支持明暗主题。公开源码显示其使用 Next.js、Chakra UI、Three.js 与 Framer Motion。
- 优秀点：3D 狗成为高度可记忆的个人符号；暗色界面、圆角信息条和头像统一成温和的“数码手作”气质；产品 Inkdrop、YouTube 和作品集都与人物故事相连。
- 局限：3D 内容加载期间首屏上方会出现较大空白，且身份正文被推到下半屏；对于求职用途，视觉成本和维护成本偏高。
- 可迁移：宋林蔚站可以有一个轻量“Agent 运行轨迹/窗口状态”签名视觉，但最多占首屏 35%–40%，无需 WebGL；`prefers-reduced-motion` 下必须静止，姓名、定位、项目 CTA 在资源未加载时也始终可见。

### 8. EGOIST：敢于只展示真正重要的东西

- 链接：[站点](https://egoist.dev/)
- 事实：首页只有侧栏和主体两组内容：Projects 首先显示 ChatWise（AI chat app），Essays 随后列出中英文文章；About、Uses、Donate、RSS 均为次级入口。
- 优秀点：没有无意义技能条、装饰性数据和重复按钮；重点产品在第一屏出现，访客立即知道作者最近在做什么。中英文文章标题自然共存，没有逐句翻译。
- 局限：极简到几乎没有职业背景与项目证据，更适合已有产品知名度的作者；只有文字链接，不能展示产品界面和工程复杂度。
- 可迁移：主页精选项目严格控制为 2–3 个，宁缺毋滥；但每个项目需补“问题—系统—结果”三层信息和一张实物截图，避免只剩仓库名。

### 9. Randy Lu：可信的个人叙事比口号更有温度

- 链接：[站点](https://lutaonan.com/)
- 事实：首页先显示头像、博客定位、咨询与 RSS，随后用一段自然中文交代编程起点、工作经历、当前独立产品和写作动机，并把 EpubKit、Notepal、Browserfly 等产品直接链接在正文中。
- 优秀点：没有“热爱技术、追求卓越”一类泛化句，而是用时间、公司和正在做的产品建立可信度；文字版式舒展，适合中文长句。
- 局限：重要产品只是段落内链接，扫描者可能略过；长叙述不适合放在求职首页的第一屏。
- 可迁移：About 采用一段真实、具体、第一人称的中文叙事；段落之后立即把其中提到的项目提升为视觉卡片，不让核心证据埋在正文。

### 10. Xuanwo：技术文章列表也可以像工程日志一样高效

- 链接：[站点](https://xuanwo.io/) · [About](https://xuanwo.io/about/)
- 事实：站点用“通过开源和 Rust 实现数据自由 / Achieving Data Freedom Through Open Source and Rust”建立长期主题；文章行包含日期、标题、摘要、标签与阅读时长，导航覆盖 Archives、Categories、Tags、Series、Sketches、Links、Blogroll，并提供语言与主题入口。
- 优秀点：每一篇文章在列表里就暴露足够判断依据；Series 和 Sketches 把系统性写作与轻量想法分开；中英文有共同品牌主张，但内容按语言模式呈现。
- 局限：博客优先，项目、履历和可联系状态不在首屏；长期维护两套语言内容需要明确同步规则。
- 可迁移：宋林蔚的 Writing 区使用日期 + 结论型标题 + 1 句摘要 + 阅读时长，并把“论文解读 / Agent 工程 / 项目复盘”做成系列；英文只翻译核心案例与履历，避免承诺全量双语博客。

### 11. Hux Blog：经典大图能造氛围，也会暴露内容老化

- 链接：[站点](https://huangxuan.me/)
- 事实：首页使用大幅摄影背景、超大站名和一句中文标语，正文区用文章摘要和 Featured Tags 导览；当前首页可见的最新文章日期为 2021 年。
- 优秀点：首屏极具辨识度，摄影与个人品牌天然关联；标签云给长期内容提供第二条探索路径。
- 局限：大图几乎占满首屏，职业身份和项目不可见；内容更新时间一旦过旧，会让“精致视觉”反向强化网站缺乏维护的印象。
- 可迁移：若使用大幅视觉，必须叠加当前身份、状态和项目入口；首页显式展示 `Updated 2026.08` 或最近项目发布日期，让维护状态可见。

## 适合宋林蔚站点的区域化与双语建议

### 中文优先，但不要把两种语言挤在同一屏

- 默认中文，导航提供明确的 `中 / EN` 切换；英文页是独立语言模式，而不是每个标题后面再跟一遍英文。
- 姓名首次出现建议写为 `宋林蔚 / Linwei Song`；后续中文页面只用中文名，英文页面只用 `Linwei Song`。
- 核心 CTA 可采用短双语标签：`看项目 / Projects`、`简历 PDF / Résumé`、`GitHub`。正文不要逐句双语。
- 英文优先覆盖：首页定位、两项旗舰项目、工作/教育时间线、论文摘要、联系信息。中文博客无需为了“看起来国际化”全量翻译。

### 按招聘者的 5 秒、15 秒、60 秒设计

- **5 秒：**姓名、目标方向（大模型应用 / AI Agent 工程）、当前状态、两枚主 CTA 必须在首屏无需滚动可见。
- **15 秒：**紧邻首屏展示 4 个可信证据，例如 `2 项旗舰 Agent 系统`、`2 段工程实习`、`2 篇研究工作`、`蓝桥杯国赛一等奖 · 全国第 5`；数字必须来自简历或仓库，并标明更新时间。
- **60 秒：**两项旗舰项目各用“问题 / 系统 / 结果”三行，加架构、截图、仓库和案例详情；随后才是经历、研究和文章。

### 建议的信息架构

1. **Home**：定位、当前状态、证据数字、2 项旗舰项目、近期经历、研究成果、联系入口。
2. **Projects**：先按 `Agent 产品`、`本地智能`、`研究与评测`、`工程工具` 分组，再展示仓库；每项标注角色、阶段、技术栈、结果与更新日期。
3. **Resume**：粘性目录 + 时间线；保留 PDF 下载，网页版适合快速扫描。
4. **Research**：论文/研究工作独立呈现，给出问题、贡献、状态和可公开链接，避免只列论文标题。
5. **Writing**：项目复盘、Agent 工程、论文阅读三个系列；文章列表带日期、摘要和阅读时长。

### 视觉语言：编辑式“技术档案”，配一个轻量签名视觉

- 取 Anthony Fu 的证据密度、Shu Ding 的编辑式目录、Innei 的柔和关键词动效、Tw93 的对比状态条；不要简单复制任一站点的皮肤。
- 中文正文使用系统中文字体栈，正文不小于 16px、行高约 1.65；英文/数字可使用等宽字体形成工程感，但不要让整页中文都变成等宽体。
- 首屏签名视觉可以是“Agent 节点运行轨迹”或“本地窗口状态矩阵”，使用 CSS/SVG 即可；视觉必须表达 Agent 工作流，不做与履历无关的粒子背景。
- 项目截图应占卡片的主要视觉面积，卡片标题前先给项目结论；Hover 只补充信息，不能承载唯一内容。
- 动效时长控制在约 180–360ms，支持 `prefers-reduced-motion`；移动端取消粘性侧栏和复杂轨迹动画。

### 中国访问环境与维护策略

- GitHub Pages 首屏不依赖 Google Fonts、第三方 JS、实时 GitHub API 或大型 WebGL；字体优先系统栈，图片使用本地压缩资源。
- GitHub Stars、文章数等易变化数据使用“截至 YYYY.MM”的静态快照并链接来源，不在首屏异步请求，避免加载失败显示 0。
- 页脚显示 `Last updated / 最近更新`，项目卡显示各自更新时间；一个长期不变的版权年份不能代替维护信号。
- 邮箱、GitHub、简历 PDF 保持一跳可达；手机号等敏感信息继续只存在于用户明确提供的简历，不默认公开到网页。

## 对本次改造的明确取舍

### 应采用

- 首屏即见身份、目标方向、当前状态、旗舰项目和简历入口。
- 项目按能力主题组织，并用可核验结果而非技能词云证明能力。
- 中文优先、整页切换英文；中英文共享同一内容结构。
- 一处高识别度但轻量的 Agent 签名视觉。
- 静态、快速、可访问，所有核心信息在 JavaScript 失败时仍能阅读。

### 应避免

- 把完整简历原样塞进首页，或逐句同时展示中英文。
- 3D/WebGL、全屏视频、长时间 loading 抢占首屏。
- 技能进度条、自我评分百分比、没有来源的“精通”标签。
- 仅展示仓库名或技术栈，不讲问题、本人角色和结果。
- 依赖实时 API 的 Star/贡献计数，以及更新失败时的空数据。
- 视觉炫技先于个人身份；招聘者不应滚动一整屏才看到第一个项目。

## 研究结论

最适合宋林蔚的方向不是“传统简历站加更多卡片”，而是一个**中文优先的 AI Agent 工程档案**：首屏像产品发布页一样有记忆点，第二屏像优秀作品集一样展示可运行系统，继续向下才像在线简历一样完整。视觉惊喜来自与专业方向一致的轻量交互和清晰编排；可信度来自项目截图、系统结构、量化结果、论文与仓库之间的可追溯链接。
