# 首页「实践经历」栏目改造规范

日期：2026-08-11
范围：仅首页 `index.html` 中现有 `ledger-experience` 栏目
内部设计代号：**Chapter Dossier / 双章工作档案**

## 1. 本轮结论

这一栏不应继续做成缩小版简历，也不应直接复制游戏 HUD。它应借用艺术游戏里「章节选择 / 任务日志 / 角色档案」的阅读节奏，把两段实习变成两张有明确起点、角色、任务与证据的工作档案。

必须执行的决定：

1. **首页删除教育行。** 教育信息已在履历页完整呈现，在首页再次出现只会稀释两段实践的信号。
2. 栏目标题建议从「实习现场」调整为更专业的 **「实践经历」**；副标题为「两段把 Agent 推进真实流程的工程实践」。
3. 两段经历在桌面端同时可见，不做 Tab、折叠、轮播或 hover 才显示内容。
4. 当前 `.72rem` 的日期与公司名必须退出关键内容层；正文与关键信息不再使用小号等宽字。
5. 新结构采用两张「章节档案」：大编号负责视觉记忆，组织 / 角色 / 一句话任务 / 两条证据负责快速判断。
6. 游戏感只体现在**构图、编号、选中反馈和节奏**，不引入人物立绘、任务图标、稀有度、经验条、音效或伪游戏术语。

## 2. 当前问题诊断

### 2.1 内容重复

现有 `.ledger-education-line` 把硕士与本科压成一行放在两段实习后方。它既不帮助读者理解工作内容，又与履历页重复，应直接移除，而不是缩小或换位置。

### 2.2 文字层级失衡

当前样式中：

- `.ledger-experience-date` 与 `.ledger-experience-org` 为 `.72rem`，按 16px 根字号计算只有约 11.5px；
- 两者同时使用等宽字体，中文公司名显得机械、发灰、难以快速识别；
- 教育行为 `.86rem`，仍把大量次要信息塞进低权重小字；
- 角色标题很醒目，但它与公司、时间、职责之间缺少中间层，形成「大标题 + 一片小字」的断层。

### 2.3 版面过于横向

当前每行采用 `180px + 正文` 的长横向结构。日期被孤立在最左侧，正文又横跨很宽，视线需要反复横移。宽屏截图中，段落像表格记录而不像可读叙事；标题下方还有两层大间距与横线，造成呆板和空旷。

### 2.4 线条承担了过多层级

栏目标题、列表顶部、每条经历和教育行都依赖横线分隔。线条数量多，但没有建立「最近经历优先」「组织—角色—成果」的视觉顺序。

## 3. 艺术游戏 UI 调研与可迁移原则

### 3.1 NieR:Automata：克制的系统感 + 一条世界观母题

PlatinumGames 的 UI 设计师 Hisayoshi Kijima 将目标概括为「系统、克制，但仍然美」，先采用干净、平面的构成，再以细微的乐谱母题避免无味。来源：[PlatinumGames 官方 UI 设计复盘](https://www.platinumgames.com/official-blog/article/9624)。

迁移到本站：

- 保留暖纸、墨色与细线的 Evidence Ledger 基底；
- 用一条贯穿卡片的「章节刻度 / 记录线」作为唯一母题；
- 装饰不再依赖大量微型文字；
- 卡片底色保持实色，确保正文在网格背景上仍然稳定。

### 3.2 Persona 5：一个强色负责行动，不让所有元素争抢

Persona 5 美术总监 Masayoshi Sutou 说明其界面先确立主色，再反复测试黑白文字；界面反应也被要求即时、无等待。来源：[Persona 5 UI 访谈（Famitsu 访谈译文）](https://personacentral.com/persona-5-interview-ui-design-sound-music/)。

迁移到本站：

- 只让 `signal` 绿承担「编号定位、当前焦点、履历 CTA」三种行动信号；
- 不复制 Persona 的斜切、碎纸、强烈跳动与多层动画；
- hover / focus 反馈应在 180–240ms 内完成，不改变布局。

### 3.3 Pentiment：字体可以有性格，但不能牺牲阅读

Pentiment 用字体表现人物与时代，但团队也明确指出「真实却难读」不适合文字密集游戏，并借助可访问性团队校正呈现。来源：[Josh Sawyer 的字体与可读性复盘](https://www.gamedeveloper.com/design/pentiment-director-explains-how-going-all-in-on-fonts-helped-elevate-the-medieval-detective-rpg-)。

迁移到本站：

- 个性只放在章节大编号与栏目标题；
- 公司、职位、日期、摘要全部使用清晰的中文无衬线字体；
- 等宽字体只保留给纯装饰的英文索引，不承担事实；
- 不使用图片文字、自制难读字体或大段全大写英文。

### 3.4 Hades：艺术性来自一致的视觉语汇，而非堆装饰

Supergiant 对 Hades II UI 的要求同时强调一致图形语言、基于玩法需求的界面草图、字体、可访问性与性能。来源：[Supergiant 官方 UI Illustrator 说明](https://www.supergiantgames.com/blog/job-opportunity-ui-illustrator-for-hades-ii/)。

迁移到本站：

- 两段经历共用同一张「工作档案」模板；
- 每张卡只需要一个一致的几何章节标记，不为不同公司临时发明图标；
- 视觉变化由编号、边框和留白完成，不需要新图片资源。

### 3.5 Citizen Sleeper：信息界面也可以承载人文叙事

Citizen Sleeper 的作者 Gareth Damian Martin 来自图形、展览与实验文学背景，并亲自完成游戏 UI；其核心是用轻量系统呈现复杂工作处境。来源：[Citizen Sleeper 设计访谈](https://www.gamedeveloper.com/business/how-citizen-sleeper-was-inspired-by-tabletop-rpgs-and-gig-work)。

迁移到本站：

- 每段经历既要有结构化事实，也要有一句自然语言说明「做了什么」；
- 证据字段不等于技术标签墙，最多两条；
- 页面应让读者感到人在真实团队中解决问题，而非阅读一张参数面板。

### 3.6 可读性下限

Xbox Accessibility Guidelines 对 PC/VR 1080p UI 建议默认文字不低于 18px，并要求标准文字至少 4.5:1 对比；中文 / 日文 / 韩文长文本建议每行不超过 40 个字形。焦点还应通过高对比背景、边框或字重变化明确表达。来源：[XAG 101：Text display](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/101)、[XAG 102：Contrast](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/102)、[XAG 113：UI focus](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/113)。

本站不是远距离电视游戏界面，不必把所有元数据都机械放大到 18px；但本栏目应把 **18px 作为正文舒适基线，16px 作为事实元数据下限，14px 只留给不影响理解的章节索引**。

## 4. 推荐信息结构

### 4.1 栏目头部

可见内容顺序：

1. `03 / EXPERIENCE`：章节索引，仅作辅助；
2. `实践经历`：H2；
3. `两段把 Agent 推进真实流程的工程实践。`：18–20px 的短副标题；
4. `查看完整履历 →`：独立 CTA，放在两张档案之后的 DOM 顺序中；桌面可通过布局放到标题右侧，移动端必须落在两张经历之后。

栏目标题与档案区之间保持 24–32px，而不是当前接近两层行高的空白。头部只保留一条结构线。

### 4.2 双章工作档案

桌面端两张并排，均完整可见。每张档案固定采用以下顺序：

1. **章节编号**：`01` / `02`，负责视觉识别；
2. **日期**：完整、统一格式；
3. **组织**：公司名为主，计划 / 项目名为次；
4. **角色**：H3，作为卡片第一阅读焦点；
5. **任务摘要**：一句话说明做了什么；
6. **两条证据**：用「字段名 + 事实」表达，不做十几个胶囊标签；
7. 不设置卡片内部 CTA，不重复 GitHub、项目页或教育信息。

推荐可见文案：

#### 01 / 友达光电

- 日期：`2026.07 — 2026.08`
- 组织：`友达光电`；次级说明：`卓越工程师计划`
- 角色：`AI 专案实习生`
- 摘要：`为 FIDM 新产品 SOP 智撰建立领域模型，并独立重构 OpenSOP Agent 原型。`
- 证据一：`领域模型 / Model · 站点 OI · Step`
- 证据二：`交付 / OpenSOP Agent 原型`

#### 02 / 福建新意科技有限公司

- 日期：`2025.07 — 2026.02`
- 组织：`福建新意科技有限公司`
- 角色：`大模型应用开发`
- 摘要：`面向企业客服与运维 RAG，完成 Dify 工作流、多模型接入、父子分块与全文索引。`
- 证据一：`检索 / 父子分块 · 全文索引`
- 证据二：`评测 / 20 个 Golden Cases`

以上仅重组当前首页已有事实，不增加无法核验的新成果。

## 5. 视觉构图

### 5.1 桌面端（>= 1024px）

- 档案区为 2 列，列间距 20–28px；每张卡宽约 540–590px，最低高度不做强制等高之外的空白填充。
- 单卡采用 `大编号轨道 + 内容区` 的非对称结构：左侧编号轨道 72–88px，右侧内容区自适应。
- 编号轨道使用 `ledger-ink` 实色，编号用暖纸色；一条 `signal` 绿短线或圆点作为记录定位。
- 内容区使用不透明 `ledger-paper-2` 或 `ledger-white`，1px 墨色 / 中性边框；圆角最多 4–8px，也可以直角。
- 卡片不使用阴影悬浮感；允许 1px 内描边或非常弱的纸张层次。
- 正文宽度控制在约 28–36 个中文字符；不得跨越整张 1200px 容器形成长句。
- 第一张与第二张不使用不同稀有度或大面积不同颜色；时间先后只通过编号和 DOM 顺序表达。

### 5.2 平板端（640–1023px）

- 两张档案改为单列，最新经历在前；
- 编号轨道仍位于左侧，但收窄至 64–72px；
- 卡片间距 16–20px；
- 内容区横向内边距 24–28px；
- CTA 位于第二张档案之后，左对齐。

### 5.3 手机端（< 640px）

阅读顺序必须是：

`03 / EXPERIENCE → 实践经历 → 副标题 → 01 友达光电 → 02 福建新意 → 查看完整履历`

布局规则：

- 编号轨道从左侧竖栏改为卡片顶部横条，避免压缩正文宽度；
- 顶条同时放编号和日期，日期不得断成三行；
- 公司 → 角色 → 摘要 → 两条证据纵向排列；
- 卡片内容内边距 20px，卡片间距 14–16px；
- 证据字段在 360px 下允许「字段名在上、事实在下」，不得缩字保一行；
- CTA 宽度可为 100%，最小高度 48px；
- 360px、390px 均无横向滚动。

## 6. 字体与尺度

### 6.1 字体职责

- 中文与事实文字：`system-ui, "Microsoft YaHei UI", "PingFang SC", "Noto Sans CJK SC", sans-serif`；沿用现有全站无远程字体策略。
- 英文 / 数字无需强制等宽；日期使用正常无衬线配合 `tabular-nums` 即可。
- 等宽字体只允许用于 `03 / EXPERIENCE` 这类不影响事实理解的索引。
- 不在中文元数据中使用大字距；中文 `letter-spacing` 保持 `0` 或最多 `.02em`。

### 6.2 建议尺度

| 元素 | 桌面 | 手机 | 字重 / 行高 |
| --- | ---: | ---: | --- |
| 栏目 H2 | `clamp(48px, 5vw, 72px)` | `40–48px` | 800–900 / 1.0–1.08 |
| 栏目副标题 | `18–20px` | `17–18px` | 450–550 / 1.6 |
| 章节编号 | `52–64px` | `34–40px` | 800 / 1 |
| 角色 H3 | `30–36px` | `25–29px` | 750–850 / 1.18 |
| 公司名 | `18–20px` | `17–18px` | 650–750 / 1.45 |
| 计划名 / 日期 | `16px` | `15–16px` | 500–650 / 1.45 |
| 任务摘要 | `18px` | `17px` | 400–500 / 1.7 |
| 证据字段名 | `15–16px` | `15px` | 700 / 1.5 |
| 证据事实 | `16–17px` | `16px` | 500–600 / 1.55 |
| 章节索引 | `14px` | `13–14px` | 700 / 1.4 |
| 履历 CTA | `16px` | `16px` | 700 / 1 |

约束：

- 除纯装饰章节索引外，**任何承担事实的文字不得低于 15px，默认目标为 16px 以上**；
- 不通过降低透明度制造层级，优先通过字号、字重、位置和留白；
- 普通正文对比度至少 4.5:1；弱化文字仍不得低于 4.5:1，因为它们不是禁用控件；
- 摘要最多两到三行，超出时改文案，不做省略号隐藏。

## 7. 信息密度与节奏

每张档案最多保留：

- 1 个编号；
- 1 个日期区间；
- 1 个组织 + 最多 1 个计划名；
- 1 个角色名；
- 1 句摘要；
- 2 条证据。

不得新增：技术栈标签墙、教育、地点、学历、奖项、头像、公司 Logo、能力评分、进度条、状态百分比。

建议垂直节奏：

- 编号 / 日期到组织：16–20px；
- 组织到角色：8–12px；
- 角色到摘要：16–20px；
- 摘要到证据：20–24px；
- 两条证据之间：10–12px。

## 8. Hover、Focus 与动效

### 8.1 经历档案

两张档案本身不是链接，因此：

- 不显示手型光标；
- 不上浮、不缩放、不旋转；
- 不在 hover 时出现新文字；
- 可选地只把边框从中性灰提高到墨色，作为轻微纸张反馈，但不能让人误解为可点击。

### 8.2 「查看完整履历」CTA

- 默认：墨色文字、清晰边框或墨色底；最小点击区 44×44px，建议高 48px；
- hover：背景 / 前景互换，箭头最多水平移动 4px；
- `:focus-visible`：至少 2px 实线轮廓、3px offset，焦点与周围背景对比至少 3:1；
- active：轻微压下或降低位移，不改变尺寸；
- `prefers-reduced-motion: reduce` 下取消箭头位移与过渡，仅保留颜色 / 边框变化。

## 9. 语义与无障碍

- 保留 `<section aria-labelledby="experience-title">`；
- 栏目标题为 H2，每段角色为 H3；
- 每段经历使用 `<article>`；
- 日期可分别使用机器可读的 `<time datetime="2026-07">` 与 `<time datetime="2026-08">`，可见文字仍显示完整区间；
- 两条证据优先使用 `<dl>`，字段名为 `<dt>`，事实为 `<dd>`；
- 章节编号为辅助定位；若与 H3 组合会被屏幕阅读器重复，可对纯视觉副本使用 `aria-hidden="true"`；
- 颜色不是唯一信息通道，编号、标题和字段名必须始终可见；
- 200% 浏览器缩放时不能丢字、重叠或需要横向滚动阅读单行；
- 关闭 CSS / JavaScript 后，两段经历仍按新到旧顺序可读；本栏目不依赖 JavaScript。

## 10. 明确不借鉴的游戏 UI 习惯

- 不使用只有 10–12px 的 HUD 元数据；
- 不用斜切文本、纵排日期或旋转中文；
- 不用 hover 才显示任务详情；
- 不设置「当前任务 / 已完成 / 稀有度」等虚构状态；
- 不使用角色立绘、公司 Logo、纹章或无来源插画；
- 不添加音效、粒子、扫描线、闪烁光标或无限循环动画；
- 不把两段经历做成只能一次看一条的章节切换器；
- 不为了游戏感牺牲复制、选择、浏览器缩放和屏幕阅读器语义。

## 11. 实施映射

建议保留现有外层类名，减少全站影响；实现时只重构：

- `index.html` 的 `ledger-experience` 内部结构；
- `css/evidence-ledger.css` 中 `.ledger-experience-*` 与相应媒体查询；
- 删除 `.ledger-education-line` 的 HTML 与不再使用的 CSS。

不得影响履历页 `resume.html#experience` 的完整内容。最新经历继续排在第一位。

## 12. 验收标准

### 内容

- [ ] 首页完全不再显示硕士、本科或「教育：」行；
- [ ] 两段经历均完整可见，事实与当前首页一致；
- [ ] 友达光电在前，福建新意在后；
- [ ] 每段仅 1 句摘要 + 2 条证据；
- [ ] 「查看完整履历」仍指向 `resume.html#experience`。

### 可读性

- [ ] 关键事实文字计算字号均 >= 15px，正文与摘要目标 >= 17px；
- [ ] 不再用 `.72rem` 等宽字显示日期和公司名；
- [ ] 每行中文正文不超过约 40 个字形；
- [ ] 正常文字对比 >= 4.5:1，焦点边界对比 >= 3:1；
- [ ] 200% 缩放无内容丢失、重叠或双向滚动。

### 版面

- [ ] 1440–1920px 下为两张并排档案，正文没有跨越整屏的长句；
- [ ] 768px 下为一列，保持新到旧顺序；
- [ ] 360×800 与 390×844 无横向滚动；
- [ ] 手机端编号轨道转为顶部横条，正文宽度不被挤压；
- [ ] 栏目不再依赖连续三到四条横线建立层级。

### 交互与无障碍

- [ ] 静态档案不伪装成按钮，不显示手型光标；
- [ ] 键盘 Tab 只进入真实 CTA，焦点清楚可见；
- [ ] hover 不承担任何独占信息；
- [ ] `prefers-reduced-motion` 下无位移动画；
- [ ] H2 / H3 层级正确，两个 article 与证据列表语义有效。
