2026.07—2026.08 · Local small-model Agent Harness

Local Window
Copilot

面向 MiniCPM-V 4.6 Thinking（1.3B 总参数 / 0.8B LLM）的完整桌面 Agent Harness：不用云端 API，由 OCR 与 VLM 分工理解当前窗口，再用 SQLite、上下文装配和原生悬浮交互把小模型变成可持续使用的本地助手。

Problem

小模型缺的不是另一个 Prompt，而是一套可靠 Harness。

桌面助手要同时回答三个问题：眼前窗口到底写了什么、当前行为意味着什么、之前对话和长期偏好里哪些内容值得带入。把这些职责全推给 0.8B LLM，只会浪费上下文并放大误读。

01 / READ

文字与位置必须准确

数字、字段和区域位置由 OCR 提供，不要求 VLM 猜测屏幕上可直接读取的几何事实。

02 / UNDERSTAND

页面和行为需要语义

VLM 聚焦页面布局、视觉关系与用户正在做什么，把有限推理预算用在 OCR 不擅长的部分。

03 / REMEMBER

上下文不能每轮重来

窗口观察、完整对话和确认后的长期记忆需要持久化；程序重启后仍应恢复，而不是重新认识用户。

Harness

先整理感知与记忆，再把紧凑上下文交给模型。

每轮固定当前截图，按当前窗口补充真正相关的历史，压缩更早对话，并保留用户确认过的稳定信息。模型不必自己在杂乱历史里找重点。

Context

三层上下文，各自承担一种确定性。

当前场景保证回答针对眼前窗口，对话上下文保证交流连续，长期记忆只沉淀经用户确认的稳定事实。三者都由 SQLite 保存并可在重启后恢复。

01 · Current scene

  • 固定的当前窗口截图
  • OCR 文字、数字与位置
  • VLM 对布局和行为的解释

02 · Dialogue context

  • 完整对话持久化
  • 按窗口补充相关历史观察
  • 自动压缩更早对话，控制上下文长度

03 · Long-term memory

  • 用户确认后才保存稳定信息
  • 与窗口观察和对话一并存入 SQLite
  • 应用重启后恢复，不依赖云端账户

Decisions

六个决定，让 0.8B LLM 把算力花在回答上。

Harness 主动承担识别、筛选、压缩、持久化与交互控制；模型只处理已经被组织好的页面语义、必要历史与用户问题。

OCR / VLM

感知职责拆分

RapidOCR 负责可读文本与坐标，MiniCPM-V 负责布局、视觉关系和行为理解，避免重复消耗模型上下文。

PIN

当前截图固定

回答期间使用同一份当前场景，防止窗口切换后“提问时看到的内容”和“生成时使用的内容”不一致。

WINDOW

历史按窗口补充

不把所有观察无差别塞进 Prompt，只选择当前物理窗口真正相关的历史信息。

COMPRESS

早期对话自动压缩

完整记录保留在 SQLite；送给模型的早期内容压成摘要，把窗口留给当前任务。

CONFIRM

稳定信息先确认

长期记忆不静默猜测；只有用户明确确认后才保存，降低错误偏好在后续对话中反复传播的风险。

CLI / UI

命令进入悬浮窗

通过 / 管理对话、窗口、上下文与记忆，同时保留流式回答、思考状态和取消控制。

Evidence & boundaries

速度经过实测，能力边界保持明确。

项目验证的是“小模型 + 完整 Harness”在本地桌面场景的可用路径，不把参数规模、自动操作或云端服务包装成不存在的能力。

01

当前目标平台是 Windows 10/11；窗口捕获和原生悬浮交互依赖 Win32 能力。

02

OCR 负责准确读取文字与位置，VLM 负责视觉语义；任一层不确定时，不把猜测伪装成屏幕事实。

03

长期记忆只保存用户确认后的稳定信息，完整历史仍可审查和管理。

04

当前定位是本地 Copilot 与 Agent Harness，不承诺未经确认的自动桌面操作。
