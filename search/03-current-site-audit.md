# 现站与信息架构审计

> 审计日期：2026-08-09
> 审计范围：`main` 分支当前静态站源码、公开页面结构、共享 CSS / JS、已纳入站点的项目与证明材料。
> 不在本文件范围：最新版简历 PDF 的内容核对与摘录，由主任务单独完成。

## 结论摘要

现站已经具备完整的个人站骨架：身份定位清楚、项目和履历内容充足、导航与移动菜单可用、主要页面有基础 SEO 元数据，且本地校验通过 **17 个 HTML 文件、239 个本地资源链接**。它不是一个“内容不足”的网站。

当前最影响目标的三个问题是：

1. **首屏信息很多，但记忆点不集中。** 姓名、职位、定位段落、两个按钮、两个文本链接、四格近况、四项成果同时竞争注意力；真正能形成视觉记忆的旗舰项目界面或工程证据反而在首屏之外。
2. **品牌承诺与页面证据不完全匹配。** 全站反复强调 “Evidence-grounded / 证据可追溯”，但多数项目只有长段介绍和 GitHub 链接；成果截图、架构切片、可复核指标、证书、演示和案例页没有形成统一的证据链。
3. **视觉整洁但偏通用模板。** 白底、蓝色、圆角卡片、英文 kicker、标签云的完成度不错，但与大量开发者作品集相似；多个年份的 CSS 追加覆盖和几套卡片语言并存，也使视觉系统开始漂移。

因此，本轮改版应从“把所有经历都陈列出来”转为“用一条强叙事让人 10 秒内理解并记住”：

> 宋林蔚是谁 → 正在解决什么问题 → 哪两个项目最能证明 → 做到什么结果 → 去哪里看完整证据 / 简历。

## 首屏扫描审计

### 当前首屏提供了什么

桌面端 Hero 同时包含：

- 姓名和“大模型应用 / AI Agent 工程”角色；
- 一段约 80 字的工程立场；
- “查看项目 / 查看简历”两个主按钮，以及 GitHub / 邮箱两个文本链接；
- “在做 / 实践 / 研究 / 求职”四格状态；
- “全国第 5 / 10 部门 30 人 / OCR 加速 / 2 项研究”四项成果。

优点是信息完整、方向明确。问题是首屏至少存在 **8 个摘要块 + 4 个入口**，视觉权重相近，用户需要自己判断什么最重要。最具差异化的“星途知汇”和 “Local Window Copilot”没有以产品界面、流程切片或结果对比在首屏出现。

### 对用户目标的直接影响

- 招聘者能迅速知道“做 AI Agent”，但不一定能迅速回答“最强代表作是什么、本人做了什么、结果有多硬”。
- `status-panel` 与 `hero-proof-strip` 都在承担摘要职责，且后续项目、研究、关于和简历再次重复这些信息。
- 在 `<=1023px` 时 Hero 改为单列；在手机端状态四格再变为四行，后面还有四行成果。用户到达首个项目之前要经历较长滚动。
- “查看项目 / 查看简历”是通用动作；没有直接下载最新版 PDF、进入旗舰项目证据页或查看可运行 Demo 的高意图入口。

### 首屏应改成什么

保留一个明确句式：

1. **身份**：姓名 + 目标岗位 / 当前阶段；
2. **价值主张**：一句不超过 32 个汉字的定位；
3. **证明**：最多 2–3 个最强且可追溯成果；
4. **旗舰项目**：至少 1 个真实项目视觉或系统切片；
5. **动作**：`看代表项目` 为主，`下载最新版简历` 为次，GitHub / 邮箱降为辅助。

“开放实习”“预计毕业时间”等状态保留为一条轻量状态行，不再使用四格面板重复展开。

## 视觉一致性审计

### 已经做得好的部分

- 共享色彩、间距、圆角、阴影和容器变量，基础节奏稳定。
- 导航固定、按钮触达面积至少 44px、键盘焦点可见。
- 移动导航包含 `aria-expanded`、focus trap、Esc 关闭、overlay 与 `inert` 渐进增强。
- `prefers-reduced-motion` 下禁用动画，滚动 reveal 在无 JS 时仍默认可见。
- 首页的研究 / 荣誉、工具行、文章行，比单纯卡片墙更有层次。

### 当前不一致与“模板感”来源

- `css/style.css` 已约 63 KB，存在基础版、Homepage v3、2026-07、2026-08 多段追加覆盖；`--max-width`、色值、卡片与响应式规则多次重定义。短期可用，后续改一个组件容易触发隐性级联冲突。
- 文件开头写的是“单一蓝色强调、无渐变”，但后续使用多色主题、径向 / 线性渐变和不同卡片封面；设计原则与最终实现不一致。
- 首页项目使用“信号流程条”，项目页混用真实封面、吉祥物、流程条，博客又使用多色生成封面；同级内容没有共同的项目视觉框架。
- 页面大量使用“英文 kicker + 蓝色色条 + 圆角边框卡片 + 标签胶囊”，层层重复后显得像组件库展示，而不是有明确作者气质的作品集。
- Local Window Copilot 详情页内置一套 `case-*` 样式；AI Prep 和部分文章也有独立样式，导航、页头、按钮与字体层级逐渐分叉。
- 最大标题约 `3.5rem`，页面整体宽度和留白较克制，专业但缺少能在进入瞬间形成印象的排版尺度、非对称构图或项目实物。

建议确定一套明确视觉母题，例如“**工程档案 / Evidence Ledger**”：大号编辑式标题、可核验编号、证据注释、系统切片和克制的高对比色。不要再新增另一套泛化卡片样式。

## 改版优先级

### P0：本轮必须完成

1. **重构首页首屏信息层级**：删除四格近况或压缩为一行；只保留 2–3 个最强成果；加入一个旗舰项目视觉 / 证据窗口。
2. **把“项目”变成主叙事**：首页突出 2 个旗舰项目，项目页采用可扫读的案例结构，而非五张同权重长段卡片。
3. **建立最新版履历入口**：首屏和简历页都提供明确的最新版 PDF 下载 / 查看入口，网页履历与 PDF 状态同步。
4. **补齐证据链**：至少为星途知汇、Local Window Copilot、OpenSOP 提供“问题—本人贡献—结果—证据—边界”；把已有竞赛 PDF 连接到对应成绩。
5. **移动端优先压缩**：在 390×844 及 360×800 验证首两屏的核心信息与 CTA，不让状态和标签把项目推到远处。
6. **删除或改写过时信息**：所有时间、投稿状态、实习状态、项目状态与数字以本轮确认的数据源为准；旧文章可以保留历史，但必须标出“当前架构更新”。

### P1：与视觉重构同步完成

1. 建立一套独特且可延展的视觉母题，合并 CSS 级联，统一首页、项目、简历、关于、博客与案例页的排版和交互。
2. 调整导航优先级，使招聘场景路径更短：`首页 → 项目 → 履历 → 文章 → 关于`；AI Prep 作为工具产品入口，不与履历争抢主导航。
3. 为旗舰项目补真实 UI / 架构 / 输出物视觉，统一图像比例、标注、alt 和说明文字。
4. 修复公共页面的 landmark、skip link、canonical、OG / Twitter、结构化数据、sitemap 与模板页索引问题。
5. 让博客正文与列表服务端可见 / 静态可见，JS 只负责筛选和渐进动效。
6. 优化 PNG、图片尺寸、lazy-load 与 Demo 嵌入策略；对首屏做实际性能验证。

### P2：上线后迭代

1. 增加案例筛选、项目状态筛选或文章主题筛选，但仅在内容量确实需要时启用。
2. 视求职对象增加中英双语摘要，不做整站机械双语复制。
3. 增加 RSS、轻量匿名统计、外链与时效内容自动巡检。
4. 为研究和开源项目增加变更日志 / 最近更新，展示持续维护而不是一次性发布。

## 可直接写入 Spec 的验收标准

### 10 秒理解

- 新访客在桌面首屏能回答：姓名、目标方向、两个代表项目、至少两项硬结果、下一步点击什么。
- 首屏主标题只有一个；定位正文不超过 2 行或约 60 个汉字；主要 CTA 不超过 2 个。
- 项目 / 履历的主入口在视觉上显著高于邮箱、GitHub、博客等辅助入口。

### 项目扫读

- 每个旗舰项目在不展开长文时即可看到：`状态 / 时间 / 角色 / 问题 / 核心贡献 / 结果 / 技术 / 证据入口`。
- 首页突出不超过 3 个项目，其中至少 1 个带真实产品画面或可解释的系统视觉。
- 每个公开指标都能找到口径、测试、证书、仓库文档或明确的“不可公开”边界；不以装饰性数字替代证据。

### 移动端与可访问性

- 360×800、390×844、768×1024 无横向滚动，首两屏出现旗舰项目入口。
- 全站仅键盘可完成导航、筛选、Demo 入口、下载简历和联系；焦点样式清晰。
- 所有页面具备唯一 H1、`<main>`、skip link；交互控件有可访问名称；图片 alt 准确，装饰图为空 alt。
- 文本对比达到 WCAG AA；普通触控目标至少 44×44px；`prefers-reduced-motion` 下无强制位移动效。

### SEO 与分享
