# 艺术向游戏 UI 调研：把“实习现场”从表格改成可读的任务档案

日期：2026-08-11
用途：为 fjnuslw.github.io 的履历 / 经历 / 项目与文章栏目提供视觉与字体依据
范围：只研究菜单、履历、任务日志、角色档案、章节列表等信息界面；不借鉴战斗 HUD、血条、准星或纯装饰性科幻面板。

## 0. 结论先行

本轮不应把网站“做成游戏”，而应借游戏 UI 解决三个真实问题：

1. **选择态必须醒目**：像 Persona 5 一样，让当前重点在字号、明暗、面积和位置上同时获胜，而不是靠一行 12px 灰字提示。
2. **信息层级主要靠排版，不靠更多颜色**：像 NieR:Automata 一样，用字号、字重、线宽、底色深浅区分层级，保留一枚强调色。
3. **长文本首先要舒适**：像 Disco Elysium 的跨设备改造一样，把观看距离、行宽和字号当作布局输入，而不是最后补救。

最适合本站的组合不是完整复刻某一款游戏，而是：

> **NieR 的暖纸色与克制结构 + Control 的大字定位锚点 + Persona 的明确选择反馈 + Citizen Sleeper 的任务卡信息组织 + Disco Elysium 的阅读尺度。**

具体到首页“实习现场”：删除重复的教育信息；两段经历改为两张可点击的“任务档案”，每张只保留日期、公司 / 计划、岗位、1 句职责、1–2 个结果证据。所有承担实际信息的文字在桌面端不小于 16px，正文以 18–20px 为主。

## 1. 研究方法与证据等级

### 1.1 证据等级

- **事实**：开发者访谈、官方开发博客、设计师本人作品说明或平台官方无障碍规范明确陈述。
- **观察**：从可访问的游戏界面截图 / 视频档案直接看到的构图、字号关系、颜色和交互状态。
- **推断**：将上述事实或观察迁移到中文个人作品集的设计建议；不声称这是原游戏团队的原意。

下文会明确标注三者，避免把“看起来像”写成开发者结论。

### 1.2 主要资料

- Persona 5：CEDEC+KYUSHU 2017 开发面板转述与开发者访谈，辅以菜单截图分析。
- NieR:Automata：PlatinumGames 官方 UI 设计博客与界面截图档案。
- Disco Elysium：The Final Cut 首席 UX 设计师的项目复盘、开发访谈及 Journal 截图。

Game UI Database 本轮搜索时被 robots.txt 阻止访问具体页面，因此本文没有把无法实访的页面当作证据；同类截图核验主要使用可访问的 [Interface In Game](https://interfaceingame.com/) 和官方 / 开发者资料。

## 2. 样本一：Persona 5 —— 重点不是“花”，而是选择态毫不含糊

### 可核查来源

- [Persona 5 UI 概念与开发面板（Persona Central 对 CEDEC+KYUSHU 2017 的转述）](https://personacentral.com/persona-5-panel-concept-development-ui/)
- [Persona 5 开发者访谈：UI、声音与音乐](https://personacentral.com/persona-5-interview-ui-design-sound-music/)
- [Famitsu：Persona 5 UI 制作过程（原始日文报道）](https://www.famitsu.com/news/201711/13145540.html)
- [Persona 5 主菜单分解档案](https://p5ui.tumblr.com/post/158342869579/command-menu-main-menu)

### 事实

- 开发面板将 Persona 系列 UI 描述为既承担信息传递，又承担整个项目“包装”的图形设计系统；制作顺序先确定主色，再确定标题标志和关键字体。
- Persona 5 刻意减少副色，让红色保持主导；易用性不只依赖颜色，还使用视线引导线、位置、角度和明暗来表现信息优先级。
- 面板明确提到：高优先级区域亮度更高，低优先级区域亮度更低；布局和角度变化帮助用户确认自己所处的位置。
- 美术总监 Masayoshi Sutou 在访谈中强调菜单要即时打开、没有延迟；每个菜单项都有动画，但响应速度是前提。

### 观察

- 菜单项并非“全部同样大、仅改文字颜色”。被选中的项目会变大、获得实色块和更强轮廓，未选择项仍可辨认但明显退后。
- 红、黑、白构成非常强的面积对比；单屏颜色少，但不是“低对比”。
- 斜切、手写感与剪贴画感负责性格，规则明确的排列和强选择态负责可用性。

### 可迁移推断

- 首页经历区可以学习它的**差异化选择态**：默认卡片清楚可读，悬停 / 聚焦后用一整块信号色、标题放大 4–8%、箭头位移和边框加粗来反馈。
- 只借“重点的面积变化”和“单一主色”，不复制漫画字体、极端倾斜、多层碎片或人物剪影。
- 当前站点“巨大栏目标题 + 大量微小元数据”的问题，本质是层级跨度过大。Persona 的有效做法不是让次要信息消失，而是让它保持可读，再让重点更强。

### 不应照搬

- 高频抖动、旋转、快速闪切；
- 每个按钮不同形状；
- 依赖红色单独表达状态；
- 把整段中文正文做成倾斜或手写字。

## 3. 样本二：NieR:Automata —— 暖纸色、字体粗细和细线足以建立完整系统

### 可核查来源

- [PlatinumGames 官方博客：UI Design in NieR:Automata](https://www.platinumgames.com/official-blog/article/9624)
- [NieR:Automata 界面分类档案：Items、Intel、Chapter Select 等](https://interfaceingame.com/games/nierautomata)

### 事实

- UI 设计师 Hisayoshi Kijima 将概念概括为“系统、无菌，但仍然美”；基础是干净、优雅的扁平设计，再用非常克制的乐谱线条意象避免无味。
- 界面以暖米色为核心，限制颜色数量；信息变化主要依赖字体颜色的深浅、字重和粗细，必要时才使用暗红橙色。
- 菜单目标是让不熟悉大型游戏的人也能使用；核心操作被压缩到摇杆与确认 / 返回，屏幕操作说明也被限制。
- 扁平界面只加入很淡的网格、边缘失真和模拟屏幕质感；这些效果是氛围层，不承担关键含义。

### 观察

- Items、Intel、Chapter Select 等页面长期复用相同骨架：顶部分类、左侧列表、右侧详情、底部操作提示。用户进入新内容时不必重新学习布局。
- 大量细线并不是均匀铺满，而是形成明确的栏间界线；选中项通常有整行底色或反转，不靠微小圆点。
- 暖米色降低了纯白页面的刺眼感，深褐黑文字仍保持清晰。

### 可迁移推断

- 本站已有纸色背景非常适合继续发展，不需要换成深色“游戏舱”。
- 经历卡可采用同一骨架：左边只放编号 / 日期，右边放岗位与证据；两卡结构完全一致，降低扫描成本。
- 以字号和字重建立层级：岗位 32–40px、公司 16–18px、摘要 18–20px、日期 16px；强调色只给“当前 / 结果 / 链接”。
- 线条从“每行都有一条”改为“分组才出现”，避免简历表格感。

### 不应照搬

- 低对比米灰色正文；NieR 自己也经历了在柔和米色中寻找可读配色的反复试验。
- 像素字体用于中文长句；它在游戏中是世界观符号，在作品集里会损失专业阅读体验。
- 假装成系统命令、芯片槽位或故障屏幕；没有内容语义时只会增加噪音。

## 4. 样本三：Disco Elysium —— 文本密集产品必须按观看距离设计

### 可核查来源

- [The Final Cut 首席 UX 设计师 Taylor Wright 的项目复盘](https://redlamp.org/work/disco-elysium/)
- [Disco Elysium UI 开发访谈索引](https://80.lv/articles/disco-elysium-working-on-ui-design)
- [Journal / Map 界面截图与说明](https://www.shacknews.com/article/114689/where-to-get-a-map-in-disco-elysium)
- [Disco Elysium UI 基础说明](https://www.gamepressure.com/disco-elysium/user-interface/z5e3e8)

### 事实

- The Final Cut 为 Monitor、TV、Handheld 三种观看场景分别设置字体大小、布局规则和视觉调整，而不是只把同一界面等比缩放。
- 设计师还按玩家视野中的角度计算字号，并为短条目、长条目和不同数量的响应列表制作交互原型。
- 这项工作被明确描述为针对一款“以冗长文本闻名”的游戏，目标是让不同设备上的阅读自然、舒适。

### 观察

- Journal 把任务列表与地图分为两个大阅读面板；标题、技能标签、难度与任务状态形成稳定的重复节奏。
- 内容虽然多，但主要区域足够宽，关键任务有明确底色；装饰性纹理停留在面板背景，不穿过正文。
- 纵向文本区接近阅读栏而不是 HUD 小窗，用户可以沿一个方向持续阅读。

### 可迁移推断

- 履历页和文章页应针对桌面 / 平板 / 手机分别设置排版，不要只用 `transform: scale()` 或一套字号。
- 经历摘要不宜横跨整页。中文正文建议每行 28–36 个汉字，最大不超过约 40 个 CJK 字符。
- 正文和元数据都应随视口调整；移动端不是简单把 18px 降成 13px，而是维持 17–18px并重排结构。
- “次要”不等于“小到难读”：次级信息可以用较弱色和较轻字重，但字号仍须可读。

## 5. 样本四：Control —— 大字是位置锚点，红块是状态，不是背景噪音

### 可核查来源

- [Control 界面分类档案：Mission、Correspondence、Collectibles 等](https://interfaceingame.com/games/control/)
- [Control 的字体与官僚视觉系统分析](https://carlwaldron.com/the-typographic-simplicity-of-control/)
- [Control 字体如何强化世界观（Kotaku）](https://kotaku.com/the-fonts-in-control-make-its-world-feel-way-creepier-1837714580)

### 观察

- Control 的任务、档案、收集物界面使用直接的无衬线字体、大字号栏目名和成片红色作为定位锚点。
- 任务详情遵循“列表 / 当前项 / 详情”的清楚分区；正文并没有为了“超自然”气质而使用难读字体。
- 大字常用于告诉用户“你在哪里”，正文用于告诉用户“这是什么”；两者职责分开。

### 可迁移推断

- 首页栏目标题“实习现场”可以保留大字，但它下方的信息不能突然跌到 12–13px。更合理的是把大字作为场景锚点，然后使用 16 / 20 / 36px 三档建立内容层级。
- 信号色只在悬停卡、当前标签、重要结果或箭头上整块出现；不要在背景到处散落小红线。
- 可以使用大号 `01`、`02` 作为两段经历的空间坐标，但编号本身不应比岗位更抢眼。

### 不应照搬

- 全屏地点闪字、画面抖动和异常红屏；
- 大量保密章、涂黑条和档案编号；这会把真实履历伪装成角色扮演道具。

## 6. 样本五：Hades —— 装饰服务于栏目边界，正文仍然规整

### 可核查来源

- [Hades 界面档案：Mirror of Night、Keepsakes、Pact of Punishment 等](https://interfaceingame.com/games/hades/)
- [Supergiant 对 Hades II UI Illustrator 岗位的说明](https://www.supergiantgames.com/blog/job-opportunity-ui-illustrator-for-hades-ii/)

### 事实

- Supergiant 把 UI illustration 明确视为菜单概念、HUD 元素和图标的独立美术工作，而非最后加的一层通用组件皮肤。

### 观察

- Hades 的 Mirror、Keepsakes、Codex / 对话等信息界面有希腊纹样、金色边框和角色插画，但选项列表、解释文字和数值仍落在稳定网格中。
- 装饰通常集中在边框、标题端点、奖章和分隔器；文本背后保持相对安静。
- 每个系统有自己的图形符号，但字体、金 / 红 / 黑色关系和交互反馈保持一致。

### 可迁移推断

- 作品集可以给“经历”“项目”“文章”各一枚简洁图形母题，但不能给每张卡一套新风格。
- 装饰最适合放在卡片角、编号、分组标题和悬停轮廓；正文区域留白。
- 现在首页的方格背景已经承担世界观，不再需要在每条履历后增加复杂仪表或花纹。

## 7. 样本六：Citizen Sleeper —— 任务卡、状态与结果可以共处，但只展示当下所需

### 可核查来源

- [Game Design Roundtable：Citizen Sleeper 作者访谈（39:13 起讨论 Information UI Design）](https://thegamedesignroundtable.com/episode/316-citizen-sleeper-with-gareth-damian-martin/)
- [Citizen Sleeper 技能页截图（Nintendo World Report）](https://www.nintendoworldreport.com/review/60533/citizen-sleeper-switch-review)
- [Citizen Sleeper 2 官方 PlayStation 页面与界面截图](https://www.playstation.com/en-us/games/citizen-sleeper-2-starward-vector/)

### 事实

- 作者 Gareth Damian Martin 的访谈将“Keeping Design Clean”和“Information UI Design”列为独立讨论主题，说明信息组织是游戏核心设计的一部分，而不是附属 HUD。

### 观察

- 技能 / 行动界面以高对比深色底、白字和单一亮粉色状态构成；五类能力使用重复的列结构，成本、名称和结果在固定位置出现。
- 角色插画占据独立区域，不压住文字；关键行动以卡片出现，风险、技能要求和收益相邻。
- 信息很多，但一次只高亮当前可选动作；其余项目降低亮度而非缩小到不可读。

### 可迁移推断

- 每段实习可以像任务档案一样包含四个固定槽位：`时间`、`组织`、`角色`、`可验证结果`。
- 结果适合做成 1–2 个短标签，例如“独立重构 OpenSOP Agent”“20 个 Golden Cases”，而不是埋在一整句灰字末尾。
- 卡片 hover 时可以出现“查看完整履历 →”，但默认态也必须完整表达岗位与成果。

### 不应照搬

- 骰子、生命值、任务进度条、技能点等虚构反馈；网站访客没有这些游戏状态。
- 把真实工作经历写成 “QUEST ACCEPTED / XP +20”；会削弱可信度。

## 8. 跨样本规律：哪些东西真的有效

| 设计问题 | 游戏样本中的有效手段 | 对本站的落地方式 |
| --- | --- | --- |
| 用户不知道先看哪 | Persona 用面积、亮度、角度和动效共同强化选择态 | 一次只让一张经历卡成为强色块；岗位标题最大，证据其次 |
| 页面风格呆板 | NieR 用一个隐喻和少量线条建立气质 | 保留 Evidence Ledger 的纸色 / 网格，只增加一套“任务档案”母题 |
| 正文很小 | Disco 按观看距离和设备重做字号与布局 | 正文 18–20px；移动端不低于 17px；中文行宽 28–36 字 |
| 大标题抢走内容 | Control 把大字限定为位置锚点 | 栏目标题之后立刻出现同样有分量的 32–40px 岗位标题 |
| 装饰过多 | Hades 把纹样放在边框和标题，不穿过文本 | 装饰留在卡片边缘、编号和 hover；正文底保持安静 |
| 结果埋在句子里 | Citizen Sleeper 把要求、风险和收益放进固定槽位 | 每卡把 1–2 个成果做成独立证据标签 |

共同点不是“游戏感”，而是：**重点有面积、内容有容器、阅读有节奏、反馈有状态。**

## 9. 字体与排版规范（可直接进 SPEC）

### 9.1 外部可访问性基线

[Xbox Accessibility Guideline 101](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/101) 建议 PC / VR 的 1080p 默认文字至少 18px，并建议 CJK 多行文本一行不超过 40 个字形、行距至少 1.5。该规范针对游戏而非网页，因此下列值是**迁移推断**，不是对网页的强制标准。

[W3C 对 WCAG 2.2 Text Spacing 的说明](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing) 要求内容在用户覆盖为 1.5 倍行高等间距时仍不丢失功能或文本。本站应避免固定高度文字容器和截断。

### 9.2 建议字号令牌

桌面端（以 1440–1680px 宽截图为主）：

| 用途 | 建议字号 | 字重 / 行高 | 说明 |
| --- | ---: | --- | --- |
| 首页姓名 / 关键主标题 | `clamp(64px, 8vw, 136px)` | 800–900 / 0.92–1.0 | 大字可保留，但不应用于每个区块 |
| 栏目标题 | `clamp(48px, 5.5vw, 88px)` | 800–900 / 1.0 | “实习现场”等位置锚点 |
| 经历岗位标题 | `clamp(30px, 3vw, 42px)` | 700–800 / 1.15 | 必须成为卡内第一视觉层级 |
| 大摘要 / 项目价值句 | `20–22px` | 450–550 / 1.65 | 每行约 28–36 个汉字 |
| 常规正文 | `18–20px` | 400–500 / 1.65–1.75 | 默认不低于 18px |
| 公司、日期、结果标签 | `16–18px` | 500–650 / 1.4–1.55 | 不能再用 12–13px 承担信息 |
| 纯装饰编号 / 英文眉题 | `14–15px` | 600 / 1.3，适度字距 | 只能是重复信息，绝不承载唯一事实 |

移动端：

- 岗位标题 `28–34px`；
- 正文 `17–19px`；
- 公司、日期、结果 `15–17px`；
- 纯装饰眉题可降至 `13–14px`，但用户即使不读它也不能损失信息。

### 9.3 字体角色

- **中文标题与正文统一使用高质量无衬线族**：优先 `Noto Sans SC / Source Han Sans SC / 思源黑体`，系统回退 `Microsoft YaHei`。用字重而非换很多字体建立层级。
- **等宽字体只用于英文编号和短标签**：如 `03 / EXPERIENCE`、日期或技术缩写；不要用等宽字体排中文公司名和正文。
- 正文避免过细字重。纸色背景上的灰字至少使用中等深灰，不能靠 300 字重 + 低对比同时“降级”。
- 中文标题不要使用过大的英文式字距；正文默认 `letter-spacing: 0` 或极小正值。
- 若引入网络字体，建议自托管、预加载常用字重，并为字体加载前后保持接近的度量，避免布局跳动。

### 9.4 行宽与留白

- 经历摘要 `max-width: 32ch` 到 `38ch`（中文实际核验不超过约 40 字 / 行）。
- 卡内标题到摘要间距 `20–28px`，摘要到证据标签 `24–32px`。
- 两张经历卡之间至少 `20–24px` 实际空隙；不要只靠一条 1px 线分开。
- 栏目标题与第一张卡之间建议 `48–72px`，让“场景标题”和“内容”清楚分组。
- 不给两行以上正文设置固定高度；在 200% 缩放和字体覆盖后仍应自然增高。

## 10. “实习现场”推荐改造方案

### 10.1 内容删减

- **删除本区底部教育行。** 教育已经在简历 / 履历页出现，首页经历区不重复。
- 页面顶部“查看完整履历”保留，但改为 16–18px 的明确按钮或文本链接，不能比公司信息更显眼。
- 每段经历只保留：时间、组织、岗位、价值句、最多两个结果证据。

### 10.2 桌面结构

建议采用双卡“任务档案”，而不是横向表格：

```text
03 / EXPERIENCE                              查看完整履历 →
实习现场

┌ 01 / ACTIVE ──────────────────────────────────────────┐
│ 2026.07—08          友达光电 · 卓越工程师计划          │
│ AI 专案实习生                                           │
│ 参与 FIDM 新产品 SOP 智撰课题，独立重构 OpenSOP Agent。 │
│ [OpenSOP Agent] [40 OI / 324 Step 验证语料]          → │
└────────────────────────────────────────────────────────┘

┌ 02 / ARCHIVE ─────────────────────────────────────────┐
│ 2025.07—2026.02     福建新意科技有限公司              │
│ 大模型应用开发                                         │
│ 负责客服 / 运维 RAG 的 Dify 工作流与多模型接入。       │
│ [20 Golden Cases] [父子分块 + 全文索引]              → │
└────────────────────────────────────────────────────────┘
```

卡片内部建议用 `grid-template-columns: minmax(140px, .28fr) 1fr`；在 900px 以下变为单列。编号和日期是侧栏，不与正文争抢宽度。

### 10.3 视觉状态

- 默认：纸色底、深色文字、1px 深灰边，卡间真实留白。
- 首张 / hover / keyboard focus：背景变为深墨色或现有信号绿，文字反转；岗位标题轻微放大，箭头移动 6–8px。
- 动效只使用 `opacity / transform / color`，时长约 180–260ms；遵守 `prefers-reduced-motion`。
- 整卡可点击时，要有清楚的 `:focus-visible` 外框；不使用鼠标悬停作为唯一提示。
- 结果标签用实色或粗下划线，不用细小灰色胶囊堆成一排。

### 10.4 内容层级

每卡只允许五级：

1. 岗位（最大）；
2. 一句话职责 / 价值（正文大号）；
3. 结果证据（高对比标签）；
4. 公司与时间（正常可读）；
5. 编号 / ACTIVE（装饰性眉题）。

当前页面的问题是第 1 级过大、第 2–4 级一起过小。改造后第 2–4 级之间可用字重和颜色区分，但不再靠极小字号。

## 11. 文章与项目栏目可复用的同一规则

- 文章卡的摘要至少 18px；阅读时间、日期和标签至少 15–16px。
- 项目卡先显示“解决什么”和结果，再显示技术标签；技术栈不应是卡内最大元素。
- 每屏最多一个高饱和主选中块，其余用纸色 / 墨色保持节奏。
- 编号必须与可访问名称并存，例如 `02 / OpenSOP Agent`，不能只显示 `02`。
- 预览图可以强，但图上文字不能成为唯一内容；HTML 中仍保留标题、摘要和结果。

## 12. 明确禁止的“游戏化噪音”

1. XP、等级、生命值、任务完成百分比等与真实履历无关的虚构指标。
2. 扫描线、故障闪烁、持续漂浮、鼠标粒子、循环跑马灯。
3. 每个标签都使用大写英文等宽 11–12px。
4. 角色肖像、证件照或 3D 人物作为栏目主视觉。
5. 为模仿游戏而隐藏常规网页导航，或让用户学习新的操作方式。
6. 只有颜色变化、没有字号 / 轮廓 / 位置变化的状态反馈。
7. 大面积斜切导致中文阅读线不断中断。
8. 把所有内容塞进一张“仪表盘”；作品集需要自然滚动与可复制文本。

## 14. 最终设计原则

游戏 UI 最值得学习的，不是把网页包装成任务终端，而是它对注意力的尊重：玩家必须在很短时间内看懂当前位置、可选动作和后果。个人作品集也一样。

因此本轮改造应遵循：

> **先让每个字舒服地被读到，再用一个大胆状态告诉读者先看哪里。**

大字可以保留，风格可以更强，但任何真实履历信息都不应被缩成装饰。
