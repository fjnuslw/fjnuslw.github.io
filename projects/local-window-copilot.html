Problem

焦点、滚动与异步返回会让桌面 Agent 读错对象。

用户点击悬浮窗后，活动窗口已经改变；页面滚动后，刚才读到的内容离开视口；较慢的观察任务还可能在下一轮完成。Harness 需要明确“观察的是哪个物理窗口、证据来自哪一帧、结果属于哪一轮”。

01 / TARGET

焦点不等于目标窗口

在悬浮窗抢焦点前记录 PID / HWND，后续刷新同一物理窗口，避免把聊天窗本身当作观察对象。

02 / EVIDENCE

截图需要变成可追踪证据

OCR 保留文本、置信度与 Bounding Box，ScreenMap 固化结构，Evidence Graph 把跨帧出现记录连接起来。

03 / OWNERSHIP

异步结果必须属于当前轮次

PinnedScene 配合 ownership / epoch fencing，阻止过期观察覆盖当前画面或写入错误的对话代次。

Harness

先锁定对象，再分层观测并写入证据账本。

OCR 处理可直接读取的文字与几何事实，VLM 补充布局、图像和页面状态。对话生成只消费已归属当前物理窗口与当前轮次的观察。

State

观察、对话与长期记忆保留各自来源。

SQLite WAL 保存原始记录；版本化 Capsule 只负责装配长对话，不删除 Thread / Generation；Notebook 只接收来自用户原话且经接受或编辑的长期记忆候选。

01 · Observation ledger

  • Observation / OcrLayout / Occurrence
  • 文本、置信度、Bounding Box 与帧归属
  • 跨帧 Evidence Graph 保留出现关系

02 · Dialogue ledger

  • 完整 Thread / Generation 持久化
  • Capsule 带版本压缩长对话
  • 原始记录保留，服务重启后恢复

03 · Bounded Notebook

  • 候选仅来源于用户原话
  • 接受或编辑后写入
  • 支持替换、软删除与恢复

Decisions

六个决定，把窗口事实、推断与记忆分开管理。

Harness 负责对象归属、确定性识别、跨帧匹配、持久化与记忆确认；模型处理已标明来源的页面语义和用户问题。

TARGET

窗口身份先于截图

PID / HWND 标识物理对象；悬浮窗抢焦点后仍刷新原目标窗口。

FENCE

场景与轮次都有所有权

PinnedScene 与 epoch fencing 拒绝不属于当前轮次的异步结果。

SCREENMAP

OCR 结果确定性成图

PP-OCRv6 的文字、置信度与坐标先形成 ScreenMap，再交给 VLM 补充语义。

GRAPH

跨帧出现记录匹配

Unicode、几何特征与 Hungarian 匹配连接 Occurrence，支撑滚动后的证据追问。

CAPSULE

压缩不删除原记录

版本化 Capsule 控制送模长度，完整 Thread / Generation 仍可审查。

NOTEBOOK

长期记忆由用户确认

候选只取自用户原话，经接受或编辑后写入，并支持替换与软删除。

Evidence & boundaries

证据来自可追踪的窗口观察，边界保持明确。

项目聚焦 Windows 本地视觉上下文与连续记忆。每条窗口事实保留物理窗口、帧与出现记录；VLM 语义和用户确认的长期记忆分别管理。

01

当前目标平台是 Windows 10/11；窗口捕获和原生悬浮交互依赖 Win32 能力。

02

PP-OCRv6 提供文字、置信度与 Bounding Box，VLM 补充布局、图像和页面状态；两类信息保留各自来源。

03

长期记忆候选只来自用户原话，接受或编辑后进入有界 Notebook；完整对话记录保持可审查。

04

当前定位是本地 Copilot 与 Agent Harness，不承诺未经确认的自动桌面操作。
